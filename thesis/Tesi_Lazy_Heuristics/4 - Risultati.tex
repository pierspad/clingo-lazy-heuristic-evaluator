\chapter{Results}
\label{sec:results}

\section{Experimental Setup and Dataset}
\label{sec:dataset}

All experiments were executed on dedicated HPC cluster nodes requesting 4 cores, with hard limits of 600 seconds and 30~GB of RAM per run enforced by \mintinline{text}|runlim|. Both backends were compiled on the test hardware and the version of SWI-Prolog used was 10.0.2.

The evaluation covers the benchmark suite defined in Section~\ref{sec:benchmarks}:
\begin{itemize}[noitemsep,topsep=2pt]
    \item BSP: $n \in \{10, 20, \ldots, 200\}$ ($20$ instances);
    \item PUP: \mintinline{text}|double-$N$|, with $N \in \{20, 40, \ldots, 200\}$ ($10$ instances);
    \item HRP: \mintinline{text}|house-$N$|, with $N \in \{2, 4, \ldots, 20\}$ persons ($10$ instances).
\end{itemize}

Across all benchmark families, timeouts represent the exclusive first failure mode (denoted \emph{T@$N$} in the summary tables), as every failing variant encounters the 600-second time limit before exhausting the memory ceiling. Memory exhaustion is confined to very large BSP instances ($n \ge 180$) where base program grounding alone exceeds the 30\,GB budget, beyond all the first failures for BSP.

On BSP, search trajectories between C++ and Prolog coincide identically across all solved instances. On PUP and HRP there are minor discrepancies in choices that arise solely from the tie-breaking among equal-rank candidates.

Evaluating these summary tables reveals that the maximum instance size solved provides different insights depending on the problem of choice. 
\begin{itemize}
    \item \textbf{On BSP}, the solvability frontier alone is insufficient to differentiate the approaches. Variants sharing the same base encoding (\mintinline{text}|gc_noheur|, \mintinline{text}|la|, and \mintinline{text}|lc|) all stop between $n=140$ and $n=160$, constrained by the heavy grounding of the base program. What distinguishes these variants is their internal search efficiency: \mintinline{text}|la| virtually eliminates solving time and conflicts (Sections~\ref{sec:bsp-runtime} and~\ref{sec:per-decision-cost}).
    \item \textbf{On PUP}, the "alpha semantic"-like dynamic guidance enables both \mintinline{text}|ga| and \mintinline{text}|la| to solve the entire range up to $N=200$, whereas the other stalls around $N=80$ due to search space explosion. With search effectively solved, PUP isolates the cost of the heuristic representation itself: the lazy approach \mintinline{text}|la| cuts grounding time and peak memory in half compared to the static aggregate unrolling in \mintinline{text}|ga| (\textbf{12.7\,GB} vs \textbf{24.6\,GB} at $N=200$).
    \item \textbf{On HRP}, the solvability frontier is uninformative because nearly all variants solve the entire benchmark suite; the evaluation centers instead on decision quality and the severe misguidance observed in \mintinline{text}|lc|.
\end{itemize}

Some other trends emerge from the benchmarks. First, the static ground simulation (\mintinline{text}|ga|) fails prematurely on BSP at $n=70$, nine sizes earlier than the baseline, due to the combinatorial explosion of static unrolling. Second, the native C++ and Prolog backends yield identical frontiers whenever propagator queries remain cheap; where they diverge, the Prolog backend consistently fails earlier due to evaluation overhead, particularly for \mintinline{text}|lc| where the propagator is queried tens of thousands of times. Finally, \mintinline{text}|lc| illustrates two distinct failure modes caused by clingo-style aggregate evaluation over the partial assignments: on BSP, the heuristic is completely inactive because its aggregate conditions are never satisfied during search (producing zero candidates), whereas on HRP, delayed evaluation yields misleading suggestions that severely degrade search performance (both detailed in Section~\ref{sec:backend-summary}).

\section{Reduction of the Ground Heuristic Component}

The primary goal of this lazy evaluation was to reduce memory spent on materializing heuristics during grounding. This reduction can be directly observed in the number of ground heuristic objects generated as a function of instance size $n$. In standard ASP encodings, directives such as:

\begin{minted}{prolog}
#heuristic b(X) : x(X), not c(X), S = #sum{Y : c(Y)}, W = (n+1)*S+X. [W, true]
\end{minted}

incorporate the dynamic aggregate value directly into the heuristic weight. Because the atoms \mintinline{text}|c(Y)| are choice atoms whose truth values are determined only during search, the grounder cannot compute the sum ahead of time. It must therefore instantiate a separate directive for every possible $(X,S)$ pair. For $X \in \{1,\ldots,n\}$ and $S$ ranging over all reachable subset sums (i.e., integers from $0$ to $n(n+1)/2$), the total number of ground directives generated by the two symmetric rules for \mintinline{text}|b| and \mintinline{text}|c| is:
\[
2 \cdot n \cdot \Big(\tfrac{n(n+1)}{2} + 1\Big) \;=\; \Theta(n^3).
\]

In contrast, the lazy variants completely eliminate this combinatorial expansion at grounding time. The aggregate is evaluated dynamically on the current partial assignment during search, allowing the materialized heuristic representation to remain constant at just two static template facts, regardless of $n$.

\section{BSP: Runtime Behaviour}
\label{sec:bsp-runtime}

For all variants sharing the base encoding without all the grounded heuristic directives (\mintinline{text}|gc_noheur|, \mintinline{text}|la|, and \mintinline{text}|lc|), the base program grounding alone dominates overall runtime. At $n=120$, it generates $52.8$ million rules, requiring $160.9$\,s of grounding for \mintinline{text}|gc_noheur|, $159.7$\,s for \mintinline{text}|lc|, and $154.2$\,s for \mintinline{text}|la|.

However here we can see a clear difference on the different semantics over the negation: while \mintinline{text}|gc_noheur| and \mintinline{text}|lc| require $44.1$\,s and $47.5$\,s respectively, \mintinline{text}|la| completes search in just $0.04$\,s. As a result, the total runtime curve for \mintinline{text}|la| remains consistently below all other variants across the entire benchmark, directly reflecting the dramatic solving speedup shown in Figure~\ref{fig:bsp-solving}.

\begin{enumerate}
    \item \textbf{Search elimination in \mintinline{text}|la|:} the default negation and dynamic aggregate evaluation allows clingo make use of the perfect heuristic given making exactly 120 perfect choices at $n=120$.
    \item \textbf{Collapse of static simulation (\mintinline{text}|ga|):} While \mintinline{text}|ga| matches \mintinline{text}|la| perfectly up to $n=50$, its performance degrades sharply at $n=60$ ($136.8$\,s solving, $1.67$ million choices) and times out from $n=70$ onward. \end{enumerate}

\section{BSP: the Two Semantics Under the Microscope}
\label{sec:bsp-semantics}

Detailed search statistics clearly illustrate the fundamental difference between the two semantic models. As shown in Figure~\ref{fig:bsp-search}, \mintinline{text}|la| requires exactly $n$ decisions with zero conflicts for every size $n$, executing a deterministic greedy balance strategy. In contrast, \mintinline{text}|lc| exhibits search statistics that are strictly identical to the heuristic-free baseline (\mintinline{text}|gc_noheur|), recording exactly $78{,}565$ choices and $49{,}993$ conflicts at $n=120$.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.49\textwidth]{hpc/\ThesisGraphQuality/bsp/native_choices.png}
    \hfill
    \includegraphics[width=0.49\textwidth]{hpc/\ThesisGraphQuality/bsp/native_conflicts.png}
    \caption{BSP, C++ backend: choices and conflicts. \texttt{la} lies on the horizontal axis; \texttt{lc} coincides with the baseline exactly, at every size both solve, so the two curves are superimposed; \texttt{ga} leaves the chart after $n=60$. Unlike the time plots, these are exact structural counts.}
    \label{fig:bsp-search}
\end{figure}

Propagator instrumentation reveals why \mintinline{text}|lc| reproduces the baseline trajectory. Under Clingo semantics, aggregate guards on \mintinline{text}|c/1| require all elements to be assigned before the sum can be evaluated, while \mintinline{text}|clingo_not(c(X))| requires explicit falsity. During search, these conditions are virtually never met at decision points. At $n=120$, although the propagator is consulted on every decision ($78{,}565$ calls), it yields zero applicable candidates across the entire run (\mintinline{text}|avg_candidates_per_decide| $= 0.0$, \mintinline{text}|max_candidates_seen| $= 0$). The solver therefore defaults to its standard heuristic at every step. Consequently, \mintinline{text}|lc| incurs the full runtime overhead of propagator callbacks without offering any guidance.

\label{sec:per-decision-cost}

Detailed profiling on both execution backends measures this cost in terms of decision calls, candidates generated per call, query evaluation time, and trail synchronization time.

The overall overhead varies dramatically across the benchmark configurations:
\begin{itemize}
    \item \textbf{Efficient guidance (\mintinline{text}|la| on BSP):} With only 120 decide calls taking $0.62$\,ms each in Prolog (and $10^{-4}$\,ms in C++), propagator overhead accounts for just $0.05\%$ of total runtime.

\section{Two Ground Simulations of Alpha: \texttt{ga} versus \texttt{ga\_weak}}
\label{sec:ga-weak}

The following subsections examine exploratory configurations designed to isolate specific modeling decisions. 

The first comparison investigates how closely Alpha semantics can be simulated within a ground-and-solve pipeline. Section~\ref{sec:ga-simulation} defined two distinct transformations: \mintinline{text}|ga_weak|, which removes negative guards while retaining equality bindings ($S = \#\mathtt{sum}\{Y : c(Y)\}$), and \mintinline{text}|ga|, which replaces equality with dynamically unrolled monotone bounds ($S \le \#\mathtt{sum}\{Y : c(Y)\}$).

Both simulations generate the exact same $\Theta(n^3)$ ground directives as the standard ground heuristic \mintinline{text}|gc| ($1{,}120$ directives at $n=10$, $8{,}440$ at $n=20$, and $27{,}960$ at $n=30$). Retaining equality bindings does not reduce grounding size because the grounder still enumerates all subset sums. Instead, the difference lies in activation during search: equality bindings activate at most one directive only after the sum is fully determined, whereas monotone bounds activate progressively as the partial sum increases.

    \label{fig:gaweak}

Figure~\ref{fig:gaweak} illustrates the solving performance of each approach. In \mintinline{text}|ga_weak|, directives rarely activate during search; at $n=120$, it explores a noisy search trajectory ($121{,}159$ choices and $69.6$\,s solving, compared to $78{,}565$ choices and $44.1$\,s in the baseline). Simply omitting negative guards without unrolling aggregate bounds provides no effective guidance, increases solving time, and reduces reach by two sizes ($n=140$ vs $n=160$).

In contrast, \mintinline{text}|ga| unrolls aggregate bounds and successfully reproduces dynamic guidance up to $n=50$ ($n$ choices, zero conflicts). Beyond $n=50$, however, the calculated heuristic weight $((n+1)S + X)$ exceeds clasp's 16-bit integer limit ($32{,}767$). Consequently, weight rankings saturate, leading to search explosion at $n=60$ ($1.67$ million choices, $136.8$\,s) and timeouts from $n=70$. Rescaling weights to fit within 16-bit limits restores guidance at $n=70$ ($665$ choices), confirming that the failure is caused by integer overflow rather than grounding size.

These results show that ground simulation of dynamic aggregates is severely limited: partial approximations (\mintinline{text}|ga_weak|) fail to guide search, while full unrolling (\mintinline{text}|ga|) suffers from integer weight saturation. The lazy propagator bypasses both limitations, achieving optimal guidance ($120$ choices, $0.04$\,s solving at $n=120$) without static unrolling or weight bounds.

\section{Direct and Auxiliary Forms}
\label{sec:aux-form}

The \mintinline{text}|la_aux| variant tests an alternative lazy formulation where heuristic conditions and aggregate values are pre-materialized into auxiliary predicates (\mintinline{text}|h_b(X,S)|, \mintinline{text}|h_c(X,S)|) before being queried by the propagator. This experiment clarifies the distinction between reducing ground directive counts and avoiding the materialization of heuristic bodies.

Although \mintinline{text}|la_aux| uses only two \mintinline{text}|__heuristic| facts, materializing auxiliary relations reintroduces the quadratic $(X,S)$ product into the ground program. This causes severe overhead across all components:
\begin{enumerate}
    \item \textbf{Grounding expansion:} Auxiliary atoms inflate solver variables to $132{,}756$ at $n=50$ (compared to $5{,}150$ in direct \mintinline{text}|la|), with peak memory reaching $27.2$\,GB at $n=170$.
    \item \textbf{Solver overhead:} In the C++ backend, scanning auxiliary candidates increases per-decision cost with $n^2$, requiring $287.1$\,s of solving at $n=60$ and timing out from $n=70$.
    \item \textbf{Synchronization bottleneck in Prolog:} The vast number of auxiliary atoms overwhelms trail synchronization, which consumes $99.2\%$ of runtime ($383$\,s out of $386$\,s) at $n=30$, leading to timeouts from $n=40$.
\end{enumerate}
These results demonstrate that materializing heuristic bodies into auxiliary relations negates the benefits of lazy evaluation. The direct lazy representation (\mintinline{text}|la|) is essential to avoid reintroducing grounding and synchronization bottlenecks.

\section{Effect of the Constraint Formulation}
\label{sec:constr-form}

The \mintinline{text}|la_co| variant combines the lazy heuristic with a reformulated balance constraint, replacing the quadratic difference check over \mintinline{text}|sumB|/\mintinline{text}|sumC| with a single constant-bound interval constraint.

The resulting performance improvement is substantial: at $n=120$, the propositional formula shrinks from $52.8$ million rules to just $366$, reducing total Clingo runtime from $154.2$\,s (\mintinline{text}|la|) to $9$\,ms, while maintaining perfect search guidance ($117$ choices, zero conflicts). This efficiency holds up to $n=200$, which solves in $14$\,ms.

This experiment demonstrates that once lazy heuristics eliminate search overhead, the remaining performance bottleneck in BSP stems entirely from the ground materialization of the domain constraint. Combining lazy heuristics with propagation-friendly modeling resolves both search and grounding bottlenecks simultaneously.

\label{sec:hrp}

HRP evaluates heuristic semantics on rules with nested default negations but without dynamic aggregates. Because HRP instances are relatively small, nearly all variants solve every instance in under a second on the native backend, making this benchmark an ideal testbed for assessing guidance quality and per-decision query overhead.

The experimental results highlight a sharp semantic contrast:
\begin{itemize}
    \item \textbf{Alpha semantics (\mintinline{text}|la| and \mintinline{text}|ga|):} \mintinline{text}|la| matches \mintinline{text}|ga| choice-for-choice ($86$ vs $88$ choices at $N=14$, with zero conflicts for both), confirming that lazy evaluation faithfully replicates reference Alpha guidance.
    \item \textbf{Misguidance under Clingo semantics (\mintinline{text}|lc|):} In Clingo semantics, evaluating default negations on partial assignments requires established falsity (e.g., \mintinline{text}|not fullCabinet(C)|). This delays higher-level heuristic rules while allowing incomplete lower-level rules to fire, actively misdirecting search. HRP also illustrates query cost differences on the Prolog backend. Because reference heuristic rules generate over $1{,}000$ candidate pairs per decision at $N=20$, Prolog query time averages $9.7$\,ms per call. For \mintinline{text}|la|, this accounts for $1.03$\,s of the $1.55$\,s Prolog runtime (compared to $0.38$\,s on native C++). For misguided \mintinline{text}|lc|, making $73{,}143$ expensive calls at $N=14$ pushes Prolog runtime to $264.5$\,s ($99.4\%$ inside the propagator), compared to $1.80$\,s on the native backend.

\section{Native versus Prolog: Summary}
\label{sec:backend-summary}

Across the full benchmark campaign, the native C++ and Prolog backends produce identical solvability frontiers in all but five configurations. In all five cases, the Prolog backend fails earlier due to interpretation overhead:
\begin{itemize}
    \item \mintinline{text}|la| on BSP ($n=160 \to 150$) and \mintinline{text}|lc| on BSP ($150 \to 140$), where runs finish within seconds of the 600-second timeout.
    \item \mintinline{text}|la_aux| on BSP ($n=60 \to 30$), caused by synchronization overhead over millions of auxiliary atoms.
    \item \mintinline{text}|lc| on PUP ($N=100 \to 40$) and \mintinline{text}|lc| on HRP ($N=16 \to 14$), where the propagator is queried tens of thousands of times during unguided search.
\end{itemize}
Whenever propagator queries are infrequent or inexpensive, both backends achieve identical reach (e.g., \mintinline{text}|la| on PUP and HRP solves all instances on both engines).

For all ground variants, both backends execute identical encodings on the underlying solver, yielding exact matches in choice and conflict counts across all three problem families. For lazy variants, the compiled native backend evaluates consultations three to four orders of magnitude faster than the interpreted Prolog backend ($\approx 10^{-4}$\,ms vs $0.2$--$9.7$\,ms). While the native backend offers maximum performance, the Prolog backend provides greater expressiveness and debugging transparency, fulfilling their respective design roles.

\section{Summary of Results}

The benchmark evaluation yields eight principal conclusions:
\begin{enumerate}
    \item \textbf{Grounding memory reduction:} Lazy evaluation reduces the heuristic representation from $\Theta(n^3)$ directives to two constant facts in BSP. In PUP, where heuristic grounding is prominent, lazy evaluation halves both grounding time ($225.8$\,s vs $436.6$\,s) and peak memory ($12.7$\,GB vs $24.6$\,GB) at $N=200$ compared to static ground simulation (\mintinline{text}|ga|).
    \item \textbf{Separation of heuristic and base program costs:} In standard ground-and-solve systems, lazy heuristics isolate heuristic evaluation from instance size. Where the base problem encoding remains combinatorial (as in BSP), lazy evaluation eliminates search time ($0.04$\,s vs $44.1$\,s) while overall scaling remains bounded by base program grounding.
    \item \textbf{Importance of heuristic semantics:} Semantic interpretation is decisive. Alpha semantics achieves optimal greedy decisions on BSP ($n$ choices, zero conflicts) and faithful guidance on HRP. In contrast, Clingo semantics is completely inert on BSP (generating zero candidates) and actively harmful on HRP (causing multi-order-of-magnitude search degradation). On PUP, where encodings are structurally identical, Alpha semantics solves $N=200$ in $272$ choices while Clingo semantics times out.
    \item \textbf{Limits of static aggregate unrolling:} Simulating dynamic aggregates via ground unrolling (\mintinline{text}|ga|) is viable only on smaller instances. On BSP, integer weight bounds ($32{,}767$) cause \mintinline{text}|ga| to fail at $n=70$, while lazy evaluation handles arbitrary instance sizes without static bounds.
    \item \textbf{Space-time trade-off:} Lazy evaluation successfully shifts combinatorial cost from grounding memory to decision-time computation. The runtime overhead factorizes into decision frequency multiplied by per-consultation cost, making lazy evaluation most efficient when heuristic guidance is effective.
    \item \textbf{Exploratory modeling controls:} The exploratory variants validate specific architectural choices: \mintinline{text}|ga_weak| shows that omitting negative guards without unrolling yields no search guidance; \mintinline{text}|la_aux| shows that pre-materializing heuristic bodies reintroduces grounding and synchronization bottlenecks; and \mintinline{text}|la_co| shows that combining lazy heuristics with constraint reformulation solves BSP up to $n=200$ in milliseconds.
    \item \textbf{Engine comparison:} The compiled native C++ and interpreted Prolog backends produce consistent scientific results, with the native backend providing three to four orders of magnitude faster per-query evaluation.
    \item \textbf{Comparison with native lazy systems:} Clingo with lazy heuristics closely matches the search trajectories of native lazy systems like Alpha. On PUP, \mintinline{text}|la| achieves runtime within a factor of $4.6\times$ and peak memory within $1.2\times$ of Alpha, while avoiding the static unrolling overhead of standard ground ASP solvers.
\end{enumerate}
