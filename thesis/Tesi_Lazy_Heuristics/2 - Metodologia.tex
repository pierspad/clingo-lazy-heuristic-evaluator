\chapter{Methodology}
\label{sec:methodology}

\section{The Experimental Design: Two Axes, Four Variants}

Every experiment in this thesis compares encodings of the same problem that differ in how the domain-specific heuristic is represented and interpreted. The rules that define the problem, its guess and its constraints, are held fixed across the variants of a family; what varies are the two properties that Section~\ref{sec:bg-heuristics} and Section~\ref{sec:bg-alpha} identified as the points on which Clingo and Alpha disagree, and they vary independently.

The \emph{approach} axis fixes where the heuristic is evaluated. In the ground-and-solve approach the heuristic is written with native \mintinline{text}|#heuristic| directives: Gringo expands them before search and Clasp's Domain heuristic consumes the resulting ground objects. In the lazy approach the heuristic remains a handful of ground facts, \mintinline{text}|__heuristic(...)| for the native backend and \mintinline{text}|heuristic("...")| for the Prolog one, which the propagator reads at its initialization and evaluates at every decision step against the partial assignment.

The \emph{semantics} axis fixes how a heuristic condition reads partial information: the Clingo-like semantics, under which \mintinline{text}|not a| holds only once $a$ has been assigned false and an aggregate has a value only once its sources are determined, against the Alpha-like semantics, under which \mintinline{text}|not a| holds as soon as $a$ is not assigned true, and an aggregate is computed over the atoms currently true. Only the second reading makes a heuristic dynamic in the sense of reacting to a partial assignment during search, as motivated in Section~\ref{sec:motivation}: an instruction such as \enquote{prefer the element whose insertion keeps the two sums balanced} presupposes that the sum can be evaluated against an assignment that is still being built; under Clingo's semantics, that sum simply has no value until it is too late for the guidance to matter.

\includegraphics[width=0.94\textwidth]{axes}
\caption{The experimental matrix. Prefixes name the approach, suffixes the semantics.}
\label{fig:axes}
\end{figure}

Crossing the two axes yields the four variants that the rest of the thesis refers to by: \mintinline{text}|gc| and \mintinline{text}|ga| for the ground approach under the Clingo and the Alpha semantics, \mintinline{text}|lc| and \mintinline{text}|la| for the lazy evaluated one, the prefix naming the approach and the suffix the semantics. To them is added the heuristic-free baseline \mintinline{text}|gc_noheur|, which carries the same domain logic with no heuristic at all and measures what the solver does when it is left alone (Figure~\ref{fig:axes}).

Ideally, changing the approach or semantics should modify only the heuristic representation. On BSP, this control is exact, as the lazy encodings simply add two facts to the baseline program. On PUP and HRP, however, lazy encodings require auxiliary predicates to expose aggregate sources and align negative conditions, yielding a ground program measurably larger than the baseline (Sections~\ref{sec:benchmarks} and~\ref{sec:pup-encoding}). Nevertheless, when comparing the lazy variants among themselves, such as \mintinline{text}|la| against \mintinline{text}|lc| across all three families, these auxiliary predicates are shared by both encodings; therefore, this difference disappears and variable isolation remains exact by construction.

\subsection{Simulating Alpha in Ground Clingo}
\label{sec:ga-simulation}

The \mintinline{text}|ga| encodings apply two systematic transformations to \mintinline{text}|gc|.

The first transformation drops negative literals that test the partial state (such as \mintinline{text}|not c(X)| in BSP, \mintinline{text}|not not_assigned_sensor(S)| in PUP, and guards like \mintinline{text}|not fullCabinet(C)| in HRP). 
Under Alpha-like semantics, these literals are satisfied by unassigned atoms as well as false ones. Since a target atom is unassigned at the moment a decision is evaluated, dropping the negative literal altogether provides the closest approximation in ground Clingo; this is harmless in practice because the solver never re-decides an atom that is already assigned.

The second transformation replaces the equality condition with a \emph{lower/upper} bound. For BSP:

\begin{minted}{prolog}
sum_value(0..tot).
#heuristic b(X) : x(X), sum_value(S), S <= #sum{Y : c(Y)},
    W = ((n+1)*S)+X. [W, true]
\end{minted}

Instead of binding $S$ to the final value of the sum, the directive is unrolled over all candidate values \mintinline{text}|sum_value(S)| and guarded by the condition $S \le \#\mathtt{sum}\{Y : c(Y)\}$. During search, as soon as the partial sum reaches a bound $S$, every directive with that bound becomes applicable; among the applicable ground directives for the same atom, Clasp's Domain heuristic retains the one with the maximum weight, which corresponds exactly to the \emph{current} value of the aggregate. The max-weight selection thus reconstructs the dynamic aggregate at solving time. For aggregates whose contribution to the weight decreases rather than increases (such as the free-capacity terms $N_0,N_1,N_2$ in PUP) the same transformation is applied with the bound $V \ge \#\mathtt{max}\{\ldots\}$, so that the max-weight selection picks the smallest proven value.

This simulation is faithful, but its price is exactly the combinatorial explosion that motivated the thesis: one ground directive per point of the product of the unrolled domains, measured in Chapter~\ref{sec:results}.

\subsection{Weights, Priorities, and Flattening}
\label{sec:flattening}

Section~\ref{sec:bg-alpha} recorded that the two systems read the annotation $[W@P]$ of a heuristic differently. In Alpha, the pair is an \emph{absolute} rank over all heuristic instances, read lexicographically as $(P,W)$: the priority $P$ is a global level and decides first, so no instance of level $P$ is considered while an instance of a level $P' > P$ is still applicable, and the weight $W$ only orders the instances that share the same level. In Clingo, the evaluation is different: $P$ is local, arbitrating only between heuristics relative to the \emph{same} target atom, while the order in which distinct atoms are decided comes from the weight alone. An encoding written for Alpha therefore cannot be handed to Clingo verbatim.

The intended order can nevertheless be recovered, by \emph{flattening} the level into the weight:
\[
W_{\mathit{flat}} \;=\; W + P \cdot M,
\qquad M > \max W - \min W ,
\]
where the intra-level weights $W$ range over $[\min W, \max W]$ and the level multiplier $M$ is larger than that range. Under this condition $W + P\cdot M > W' + P'\cdot M$ holds whenever $P > P'$, regardless of the two individual weights, and reduces to $W > W'$ when $P = P'$: the total order induced on the atoms is then the one Alpha's absolute levels induce. When all weights are non-negative, which is the case in every encoding of this suite, $M > \max W$ suffices.

Each benchmark fixes its own $M$. In the PUP encodings $M$ is the constant offset $100{,}000$ added to the zone weights, against a maximum sensor weight of $26{,}220$ on the benchmark instances; in HRP $M$ is derived from the instance as \mintinline{text}|levelMul(LM) :- LM = MC + MR + 10| over the maximum cabinet and room identifiers, which gives $16$ on the smallest instance and $54$ on the largest. BSP doesn't need a multiplier, as discussed in Section~\ref{sec:bsp}.

The rule has one further condition, which is not a property of the theoretical order but of the machine that consumes it. Clasp stores the weight of a \mintinline{text}|#heuristic| modification in a signed 16-bit integer field and clamps any value exceeding $32{,}767$. Consequently, two ground directives whose weights both exceed $32{,}767$ become indistinguishable to Clasp's Domain heuristic. A flattened weight must therefore satisfy $W + P\cdot M \le 32{,}767$ for the ground variants to rank as intended. 
HRP stays far below this bound; PUP exceeds it on the zone directives, with the consequences discussed in Section~\ref{sec:pup}; and BSP, whose maximum weight grows as $\Theta(n^{3})$, crosses it within the benchmarked range, as analyzed in detail in Section~\ref{sec:ga-weak}. The lazy backends are not subject to this bound because they rank targets internally and hand Clasp a ready decision rather than a weight.

The suite adopts Clingo's convention in \emph{all four variants and in both backends}: absolute levels always live in the weight, simplifying the propagator as it does not need to account for a separate priority field. Once global levels are folded into weights, weight becomes the sole ordering criterion under both semantics. Accordingly, the native lazy language (Section~\ref{sec:dsl}) omits the priority field entirely.

A last convention concerns empty aggregates: \mintinline{text}|#max| over an empty set is $0$ in Alpha but $-\infty$ (\mintinline{text}|#inf|) in Clingo. All encodings therefore write \mintinline{text}|#max{0; ...}| with an explicit neutral element, and both lazy backends implement the same rule (the native \mintinline{text}|MaxState| returns $0$ when empty; the Prolog runtime defines \mintinline{text}|dyn_max| with a $0$ default).

\section{System Architecture}
\label{sec:architecture}

The project maintains two modified copies of Clingo. They share the same upstream sources and differ only in their extensions: the build in \path{clingo-native} carries the C++ backend, while the build in \path{clingo-prolog} carries the Prolog backend, configured with \mintinline{text}|CLINGO_USE_SWIPL=ON| so that the SWI-Prolog engine is linked in-process, making its memory impact easier to account for. In both builds, the extension lives entirely under \path{libclingo}, exposes the same class name, and is registered at the same point of \path{clingo_app.cc}:

\begin{minted}{cpp}
HeuristicPropagator my_propagator;
ctl.register_propagator(my_propagator, true);
\end{minted}

The propagator is registered on \emph{every} run of the modified binary. On a program that contains no heuristic facts, it remains inert because \mintinline{text}|init| finds nothing to watch and \mintinline{text}|decide| always returns $0$; the same binary therefore runs the ground variants and the heuristic-free baseline without requiring a separate build. The second argument, \mintinline{text}|true|, instructs Clasp to call the propagator sequentially, avoiding race conditions on the incremental state described in Section~\ref{sec:runtime}. No other parts of Clingo are modified. Figure~\ref{fig:architecture} shows the architecture of the two binary build variants.

\begin{figure}[H]
\centering
\includegraphics[width=\textwidth]{architecture}
\caption{System architecture of the two binary variants, showing their respective heuristic propagators and evaluation backends attached to Clasp.}
\label{fig:architecture}
\end{figure}

In both builds, the class implements \mintinline{text}|Clingo::Heuristic|---the propagator interface extended with the \mintinline{text}|decide| callback (Section~\ref{sec:bg-propagator}). Both backends follow the same four-step lifecycle:
\begin{itemize}[leftmargin=1.5em, itemsep=1pt]
    \item During \mintinline{text}|init|, they scan symbolic atoms for trigger facts (\mintinline{text}|__heuristic(...)| in the C++ build and \mintinline{text}|heuristic("...")| in the Prolog build), construct their runtime representation, and register watches on solver literals.
    \item During forward search, \mintinline{text}|propagate| updates internal aggregate and candidate states as watched literals become true.
    \item During backtracking, \mintinline{text}|undo| restores internal aggregate and candidate states as literals are retracted from the trail.
    \item At each decision point, \mintinline{text}|decide| either returns a signed literal for the highest-ranked target or returns $0$, delegating the decision to Clasp's fallback heuristic.
\end{itemize}
To activate this mechanism, runs are launched with the flag \mintinline{text}|--heuristic=Domain|. A detailed discussion of the architectural differences between the two backends is provided in Chapter~\ref{sec:implementation}.

The propagator never adds a constraint, never derives a literal, and never refuses one. It only reorders the decisions Clasp would have taken anyway, so the answer sets are untouched, and a heuristic can make a run slower or faster but cannot change the meaning of the encoding (detailed in Section~\ref{sec:decision}).

\section{Translation of the Heuristic Directives}
\label{sec:dsl}
\label{sec:translation}

Neither backend reads native \mintinline{text}|#heuristic| directives. Instead, a custom declarative lazy heuristic language replaces them with a single ground fact that \emph{describes} the rule.
This section presents what one may write, and what each construct means, by deriving that fact for the BSP heuristic of Section~\ref{sec:motivation} one component at a time. How the description is executed is left to Section~\ref{sec:implementation}.

The starting point is the directive as Clingo reads it:

\begin{minted}{prolog}
#heuristic b(X) : x(X), not c(X), S = #sum{Y : c(Y)}, W = ((n+1)*S)+X. [W, true]
\end{minted}

\paragraph{Target.} The target atom is \mintinline{text}|b(X)|, where $X$ ranges over the ground instances. The lazy fact specifies only the predicate name, \mintinline{text}|__target(b)|. During \mintinline{text}|init|, the propagator queries Clingo's atom table for all ground instances of \mintinline{text}|b(...)| already materialized by Gringo.

\paragraph{Positive body.} The condition \mintinline{text}|x(X)| shares its argument with the target: the candidate for \mintinline{text}|b(7)| is alive only while \mintinline{text}|x(7)| is true. A condition of this shape is written as the bare predicate name, \mintinline{text}|x|, and the propagator matches its arguments against the target tuple position by position.

However, a body predicate may have a different arity; its arguments may sit in different positions; or a value may have to be read out of it and used in the weight. The correspondence is then stated explicitly:

\begin{minted}{prolog}
__body(pred, __match(src, tgt), __bind_arg(var, idx))
\end{minted}

\mintinline{text}|__match(src, tgt)| requires the argument at the \mintinline{text}|src| position of the body atom to equal the argument at the \mintinline{text}|tgt| position of the target atom, where both \mintinline{text}|src| and \mintinline{text}|tgt| are integers. All indices are 0-based, and at least one \mintinline{text}|__match| is mandatory. \mintinline{text}|__bind_arg(var, idx)| extracts argument \mintinline{text}|idx| of the body atom into a variable.

Given the ground facts:
\begin{minted}{prolog}
score(1,10). score(2,5). score(3,7).
\end{minted}
and the target atoms:
\begin{minted}{prolog}
choose(1). choose(2). choose(3).
\end{minted}
the directive:
\begin{minted}{prolog}
__heuristic(__target(choose),
            __body(score, __match(0,0), __bind_arg(w,1)),
            __weight(w), __modifier(true)).
\end{minted}

pairs each \mintinline{text}|choose(X)| with the \mintinline{text}|score(X,W)| that agrees with it on the first argument, and binds \mintinline{text}|w| to the second argument of that atom. The weights are then $10$, $5$ and $7$, so the propagator decides \mintinline{text}|choose(1)| first.

\paragraph{Negative body.} The condition \mintinline{text}|not c(X)| likewise matches its arguments against the target tuple. Negative body literals are specified by prefixing the predicate name with \mintinline{text}|__n_|.

\paragraph{Semantics.} The reading of that negation is fixed by the \mintinline{text}|__semantics(S)| selector, which decides whether \mintinline{text}|__n_c| means \enquote{\mintinline{text}|c(X)| is assigned false} or \enquote{\mintinline{text}|c(X)| is not assigned true}. The same selector fixes the reading of aggregates, described below. It takes \mintinline{text}|alpha| or \mintinline{text}|clingo|, and defaults to \mintinline{text}|clingo|, so that a directive written without it behaves as the native \mintinline{text}|#heuristic| it replaces.

\paragraph{Aggregates.} Aggregates are evaluated lazily during search. \mintinline{text}|__bind(s, __sum(c))| binds variable \mintinline{text}|s| to the sum over the predicate \mintinline{text}|c| (by default aggregating its first argument). The operators \mintinline{text}|__count|, \mintinline{text}|__min|, and \mintinline{text}|__max| follow the same structure.

An aggregate can be restricted \emph{per target} using \mintinline{text}|__filter(src_idx, tgt_idx, offset)|, which keeps only source atoms whose argument at position \mintinline{text}|src_idx| equals argument \mintinline{text}|tgt_idx| of the target plus an optional \mintinline{text}|offset|. For instance, in PUP, retrieving the maximum number of sensors on the \emph{previous} unit ($U-1$) for a target \mintinline{text}|assigned_zone_unit(Z,U)| is expressed as:
\begin{minted}{prolog}
__bind(m1, __max(num_sensors_on_unit, 0, __filter(1, 1, -1)))
\end{minted}
where \mintinline{text}|0| selects the aggregated argument $N$ in \mintinline{text}|num_sensors_on_unit(N, U')|, and the filter matches $U' = U - 1$.

\paragraph{Weight.} Weight is expressed as a \emph{term tree} such as:
\begin{minted}{prolog}
__weight(__add(__mul(s, B), self))
\end{minted}
which represents $(s \cdot B + \mathit{self})$, where \mintinline{text}|self| is a shorthand for the target atom's argument at index 0 without requiring a variable binding.

The binary constructors \mintinline{text}|__add|, \mintinline{text}|__sub|, and \mintinline{text}|__mul| form expression trees whose leaves belong to three categories: integer constants, variables of the heuristic language, and target arguments (accessed through \mintinline{text}|self| or \mintinline{text}|__bind_target_arg(var, idx)| for any other).

At \mintinline{text}|init|, the propagator compiles all weight term trees into ASTs. During search, each active heuristic object evaluates its weight AST dynamically against the current trail state, avoiding the memory overhead of materializing them in the ground program. Only candidates with a strictly positive resolved weight are taken into account; the others are ignored, leaving their decision to the solver's default heuristic.

\paragraph{Modifier.} The \mintinline{text}|__modifier(M)| selector specifies which of Clingo's heuristic modifiers to use: \mintinline{text}|level| sets the ranking value alone, \mintinline{text}|sign| sets the preferred polarity alone, while \mintinline{text}|true| (the default) and \mintinline{text}|false| set both. 

The solver's \mintinline{text}|decide| interface expects a \emph{signed} literal, so a ranking value alone does not determine a decision. Each target keeps one slot per channel, ranking value and preferred polarity, and when several directives write to the same slot the one with the highest weight wins. This is what replaces Clingo's local priority. Across the benchmarks all directives use \mintinline{text}|true|, except for the final layer of HRP, which uses \mintinline{text}|false| to prune the remaining choice atoms.

\medskip
Assembling the components gives the fact in full:

\begin{minted}{prolog}
__heuristic(__target(b), x, __n_c, __bind(s, __sum(c)),
            __weight(__add(__mul(s, B), self)),
            __semantics(alpha), __modifier(true)) :- B = n + 1.
\end{minted}
