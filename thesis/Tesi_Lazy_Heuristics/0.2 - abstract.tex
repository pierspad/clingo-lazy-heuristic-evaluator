\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}
Answer Set Programming (ASP) provides a declarative way to describe combinatorial problems while delegating the construction and exploration of the solution space to a grounding and solving system. In ground-and-solve systems such as clingo, the relevant part of a program is instantiated before search starts. This architecture is robust and mature, but it can become expensive when heuristic directives generate a large number of ground instances, especially when the intended heuristic depends on the partial state of the computation.

This thesis presents the design, implementation, and evaluation of a lazy heuristic propagator integrated into a modified version of clingo. The work introduces a compact declarative representation based on \lstinline|__heuristic(...)| facts. These facts are read by the propagator during initialization and evaluated during search, thereby avoiding the full materialization of large families of \lstinline|#heuristic| directives. The implementation aims to preserve an operational behaviour close to clingo for the modifiers \lstinline|level|, \lstinline|sign|, \lstinline|true|, and \lstinline|false|, while making explicit the difference between Alpha-style lazy evaluation and clingo-like evaluation of negative bodies and aggregates.

The main contributions are a C++ extension of clingo built around \lstinline|Clingo::Heuristic|, a parser and runtime representation for lazy heuristic templates, incremental support for dynamic aggregates, a Python converter from native \lstinline|#heuristic| directives to lazy and auxiliary variants, and an experimental suite for Balanced Set Partitioning (BSP). The suite includes semantic validation, benchmark execution, metric collection, and automatic graph generation.

The results show that, on the BSP benchmark, the lazy representation drastically reduces the number of ground heuristic objects. At $n=100$, the native variants produce on average $1{,}010{,}200$ ground \lstinline|#heuristic| directives, whereas the direct lazy variants keep only two \lstinline|__heuristic| facts. This does not remove the grounding cost of the base program, but it compresses the heuristic component and separates the growth of the problem encoding from the runtime evaluation of the search guidance.
